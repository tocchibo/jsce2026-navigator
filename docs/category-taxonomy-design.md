# JSCE 2026 独自カテゴリ事前設計

## 1. 目的

令和8年度土木学会全国大会の748セッション・5,636講演を、公式部門やキーワード検索だけに依存せず、参加者が興味から探索できるように整理する。

この分類は公式分類を置き換えない。公式の「部門・セッション名」は原文のまま保持し、独自分類は横断的な探索用メタデータとして追加する。

## 2. 調査したデータ

- `data/sessions.json`: 748セッション、5,636講演の日時、部門、セッション名、講演番号、題名、著者、所属
- `2026/jsce2026_program_all.pdf`: 18,391ページ
  - 1～737ページ: プログラム
  - 738ページ以降: セッション情報、各講演の著者キーワード、短い内容要約、講演本文
- 対象日は2026年9月2日～4日の3日間

PDFの先頭講演で確認したところ、題名だけでは分からない研究目的、対象部位、解析手法、結果が短い内容要約に含まれている。最終分類では題名だけでなく、この内容要約と著者キーワードを主要な根拠にする。

梗概領域の5地点（2,500、6,000、10,000、14,500、18,000ページ付近）も標本確認し、いずれにも講演見出しと著者キーワードが存在した。一方、一部ページでは埋め込みフォントに対する`pdftotext`の警告も発生した。全件処理では「抽出できたものだけを分類」せず、5,636講演番号との完全照合を必須にし、欠落講演はエラーまたは人手確認へ送る。

## 3. 公式分類から分かったこと

公式部門別の規模は次のとおりで、粒度に大きな差がある。

| 公式分類 | セッション | 講演 |
|---|---:|---:|
| 第I部門 | 68 | 533 |
| 第II部門 | 38 | 288 |
| 第III部門 | 80 | 621 |
| 第IV部門 | 33 | 255 |
| 第V部門 | 123 | 976 |
| 第VI部門 | 243 | 1,774 |
| 第VII部門 | 18 | 138 |
| 共通セッション | 145 | 1,051 |

第VI部門ではトンネル、鉄道、施工管理などが細分されている一方、共通セッションにはAI、センシング、耐震、教育、宇宙、CCUS、放射性廃棄物などが同居している。また「維持管理」「数値解析」「計測」は複数部門にまたがる。

このため、単一のカテゴリ階層では以下の問題が生じる。

- 「橋梁」と「AI」のどちらを親カテゴリにするか決められない
- 「地震」は対象ではなく課題だが、公式セッション上は独立テーマになっている
- コンクリートやFRPは材料であり、橋梁・トンネルなど複数施設に使われる
- 点検、施工、維持管理は施設種類ではなく工程・目的である

独自分類は、1講演に複数の観点を与えるファセット方式とする。

## 4. 採用する5軸

機械可読な正式定義は `data/category_taxonomy.json` に置く。120講演の層化試行と全5,636講演の分布評価を反映した分類体系はv0.2、分類規則は軸別に根拠の重みを変えるv0.3である。

### 4.1 対象・分野（domain）

「何についての講演か」を表す必須軸。主題を1件、明確な副題がある場合だけ追加し、最大3件とする。

例:

- 橋梁・高架橋
- 道路・舗装
- 鉄道・軌道
- トンネル・地下空間
- 地盤・基礎・斜面
- 河川・流域
- 海岸・港湾・海洋
- 都市・地域・交通
- 環境・生態系
- 宇宙・月面インフラ

### 4.2 目的・工程（phase）

「何をしようとしているか」を表す必須軸。最大3件とする。

例:

- 調査・計測
- 設計・照査・解析
- 施工・製造
- 品質管理・検査
- 点検・診断
- 維持管理・補修補強
- 防災・避難・災害対応
- 教育・人材・合意形成

### 4.3 技術・手法（method）

「どのように取り組んだか」を表す任意軸。最大4件とする。題名の流行語だけで判断せず、内容要約で実際の利用を確認する。

例:

- AI・機械学習
- 画像解析・コンピュータビジョン
- センサ・IoT
- 3次元計測・点群・リモートセンシング
- BIM/CIM・デジタルツイン
- 数値解析・シミュレーション
- 非破壊検査
- ロボット・自動化
- 経済評価・LCA

### 4.4 材料（material）

材料自体が研究上の論点になる場合だけ付ける任意軸。構造物に使われているだけでは付けない。

例:

- コンクリート・セメント
- 鋼・金属
- アスファルト
- 土・岩・ベントナイト
- FRP・複合材料
- 副産物・再生材料
- CO2・炭素材料

### 4.5 課題・横断テーマ（issue）

分野横断で探したい社会課題・性能課題を表す任意軸。最大3件とする。

例:

- 老朽化・長寿命化
- 地震・断層・液状化
- 洪水・津波・高潮
- 土砂災害・洗掘・侵食
- 気候変動・脱炭素
- 資源循環・リサイクル
- 生産性・省人化
- 安全・リスク

## 5. 単一カテゴリではなく5軸にする例

「AI打音解析によるFRP製アンダーデッキパネル工法の間詰部評価」は、次のように表現できる。

| 軸 | タグ |
|---|---|
| 対象・分野 | 橋梁・高架橋 |
| 目的・工程 | 品質管理・検査、点検・診断 |
| 技術・手法 | AI・機械学習、非破壊検査 |
| 材料 | FRP・複合材料、樹脂・高分子材料 |
| 課題 | 生産性・省人化 |

これを「AI」だけに分類すると対象物が失われ、「橋梁」だけに分類すると技術的な興味から見つけられない。複数軸なら両方の入口から発見できる。

## 6. 判定ルール

### 6.1 根拠の優先順位

1. PDFの短い内容要約
2. 著者キーワード
3. 講演題名
4. セッション名
5. 公式部門

セッション名や公式部門だけで、個別講演へ機械的に同じタグを配らない。たとえば「維持管理」セッション内に新材料の基礎実験が含まれる場合、講演内容に従う。

### 6.2 信頼度

- `high`: 内容要約または著者キーワードに直接根拠がある
- `medium`: 題名とセッション名から一意に判断できる
- `low`: 複数解釈が残る。自動確定せず人手確認へ送る

### 6.3 境界ルール

- RC橋の耐震解析: `domain:bridge`、`material:concrete_cement`、`phase:design_analysis`、`issue:seismic_liquefaction`
- 地盤上の橋脚洗掘: 主題を梗概で判断し、橋脚応答が中心なら`bridge`、流れ・洗掘が中心なら`river_watershed`を先頭にする
- コンクリート構造物の一般的な点検: コンクリート特性が論点でなければ材料タグを付けない
- AIという語を使ったルールベース処理: 学習・推論を行っていなければ`ai_ml`を付けず、必要なら`data_platform`を付ける
- ドローンで撮影し画像解析する点検: `drone_uncrewed`と`image_processing`を併記する
- 災害シミュレーション: 災害種を`issue`、解析を`method`、避難や対応を扱う場合のみ`phase:disaster_action`とする
- CO2固定コンクリート: `material:concrete_cement`と`material:co2_carbon`、`issue:climate_decarbonization`を併記する

## 7. アプリ向けの見せ方

5軸をそのまま一度に表示すると複雑になるため、利用者向けには19個の「テーマから探す」を設ける。テーマは複数タグを束ねた表示用コレクションであり、分類データ本体とは分離する。

初期候補:

- 橋梁
- 道路・舗装
- 鉄道
- トンネル・地下
- 地盤・斜面
- 河川・水災害
- 海岸・港湾
- コンクリート
- 維持管理・点検
- 施工・自動化
- AI・DX
- 計測・モニタリング
- 防災・減災
- 環境・生態系
- 脱炭素・資源循環
- 都市・交通
- 教育・人材
- 宇宙・月面

一覧カードでは主要3タグ程度だけを表示し、詳細表示で全タグを見せる。セッションには所属講演のタグ件数を集計し、「橋梁 6/8」「AI・DX 3/8」のように表示する。

## 8. 全件分類の処理

実装した処理は次のとおり。

1. PDFの各講演冒頭ページから、講演番号、著者キーワード、短い内容要約を抽出する
2. `sessions.json`の講演番号と1対1で照合する
3. 固定した分類定義と明示規則を分類器へ渡し、各軸のタグ、信頼度、判定根拠を生成する
4. 軸ごとの上限、存在しないタグ、講演番号重複を機械検証する
5. `low`判定、タグ過多、希少タグ、無分類を人手確認する
6. 全件分布と層化標本を評価し、low判定が15%以下になるまで規則を調整する
7. 公開用JSONにはタグと信頼度だけを保存し、梗概本文は収録しない

PDFのフォント構成により本文抽出に失敗する講演は、題名だけで黙って分類しない。欠落一覧を出力し、別の抽出方法または人手確認に回す。

## 9. 品質基準

全件分類へ進む前に次を満たすことを目標とする。

- 全講演に`domain`と`phase`が最低1件ある
- `low`判定が全体の15%以下
- `domain:civil_systems`への過度な集中を避ける
- 各タグ30件または全件の0.5%未満の場合、独立タグとして残す必要性を再検討する
- 各カテゴリ50件の人手標本で適合率90%以上
- 同一シリーズ講演で不合理なタグ揺れがない
- タグの意味を変更するときは`schema_version`を更新する

## 10. v0.2層化試行

公式8分類から各15講演、計120講演を等間隔で抽出し、PDFの著者キーワードと短い内容要約を用いて試行分類した。全120講演で講演番号との一致を確認して抽出できた。

試行の結果、v0.1へ次を追加した。

- 対象・分野: 建設材料、気象・気候
- 目的・工程: 性能評価・現象解明、技術・システム開発
- 課題: 技術継承・人材確保
- 材料: 樹脂・ゴム・高分子材料へ表示範囲を拡張

詳細な件数、要確認講演、誤判定修正例は `docs/category-pilot-v02-report.md` に記録する。

## 11. 全件一次分類後の結論

このv0.2分類体系は、公式セッション名の分布、全5,636題目、PDFから抽出した全講演の著者キーワード・内容要約を基にした設計である。講演番号は `sessions.json` と完全照合し、標準の内容梗概ページ5,631件と本文1ページ目による補完5件から、欠落・重複・余剰なく全5,636件を取得した。

軸ごとに題名、著者キーワード、セッション名、内容要約の重みを変えるv0.3規則で全件を一次分類した。low判定は15%以下の事前目標を満たしている。`fallback`と上限境界が同点の`tag_limit_tie`は確認対象として保持し、公開用 `data/categories.json` には分類タグ・信頼度・確認状態だけを収録する。集計結果は `docs/category-all-report.md` を参照する。
